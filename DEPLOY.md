# Deploying TrustVault

- **Live demo:** https://trustvault-15td.onrender.com
- **Source code:** https://github.com/PailaJeevan/trustvault

The live demo runs on **Render's free plan**. Render builds the included `Dockerfile` straight from the GitHub repository, and `render.yaml` (a Render *Blueprint*) describes the whole service, including generating the two secret keys. There is no server console work, and every `git push` to `main` redeploys automatically.

---

## What is deployed

| | |
|---|---|
| Repository | https://github.com/PailaJeevan/trustvault (branch `main`) |
| Live URL | https://trustvault-15td.onrender.com |
| Host and plan | Render, web service, **Free** plan, Singapore region |
| How it is built | `Dockerfile` (Python 3.13 slim), defined by the Blueprint in `render.yaml` |
| How it starts | `docker-entrypoint.sh`: loads the demo data if the database is empty, then runs `gunicorn` (2 workers) on Render's port |
| Health check | `GET /healthz` returns `{"status": "ok"}` |
| HTTPS | Provided by Render. Plain `http://` is redirected to `https://` |

### Settings

All of these are set by `render.yaml`. Nothing secret is stored in Git.

| Variable | Value | Why |
|---|---|---|
| `TV_MASTER_KEY` | generated by Render | Encrypts every stored file (AES-256-GCM). **Back it up.** |
| `TV_AUDIT_KEY` | generated by Render, different from the master key | Signs the hash-chained audit trail. |
| `TV_DEMO_MODE` | `1` | Loads the public demo accounts and stops anyone changing their passwords, so one judge cannot lock out the others. |
| `TV_TRUSTED_PROXIES` | `1` | The app sits behind one proxy for the scheme and host, so it knows the request arrived over HTTPS. |
| `TV_FORWARDED_FOR_HOPS` | `2` | Render adds its own internal address to the end of `X-Forwarded-For`, so the visitor's real IP is the second entry from the end. A forged header sent by a client is still ignored. See PROMPTS.md entry 19. |

The `Dockerfile` also sets `TV_ENV=production`, `TV_SECURE_COOKIES=1` and the database path `/data/trustvault.db`. In production the app refuses to start without both keys, and refuses if they are the same.

### What the free plan means for judges

| | Render **Free** (what the demo uses) | Render **Starter + disk** (paid) |
|---|---|---|
| Cost | free | about US$7 a month plus a small disk charge |
| Goes to sleep | after **15 minutes** with no visitors; the next visit takes about a minute to wake | never |
| Data survives a restart, redeploy or sleep | **No.** It resets to the demo data | Yes |
| Yesterday's audit trail still there | No | Yes |

On the free plan the app **reloads the demo data every time it starts**, so the demo accounts and documents are always there, but anything done in an earlier session is gone, including the audit records of earlier attacks. This is recorded in THREATS.md (OP-17). Each audit record is also written to the log stream as a witness line, which Render keeps separately.

**Tip for judges:** open the link a minute before you start, so the server is awake.

## Part A: Put the code on GitHub

1. Install **Git** (git-scm.com).
2. Get the code on your computer:

   ```bash
   git clone https://github.com/PailaJeevan/trustvault.git
   cd trustvault
   ```

3. After changing anything, save it to GitHub:

   ```bash
   git add .
   git commit -m "Describe what you changed"
   git push
   ```

   If Git asks for a password, use a GitHub **personal access token** (GitHub → Settings → Developer settings → Personal access tokens), not your account password.

4. Never commit `.env`, `instance/`, `dev_keys.json` or any `.db` file. The `.gitignore` already excludes them. `render.yaml` and `Dockerfile` must stay in the top level of the repository.

## Part B: Deploy on Render

1. Go to **render.com** and sign in with your **GitHub** account.
2. Click **New** (top right) → **Blueprint**.
3. If the repository is not listed, click **Configure account**, choose **Only select repositories**, pick **trustvault** and save. Then click **Connect** next to it.
4. Fill in:
   - **Blueprint Name:** `trustvault`
   - **Blueprint Path:** `render.yaml`
   - **Branch:** `main`
5. Click **Apply** (or **Deploy Blueprint**). Render creates a web service called **trustvault**.
6. Open the service and click **Logs**. The first build takes a few minutes. A healthy start ends with:

   ```
   Seeded 8 users, 9 documents, 8 grants.
   Listening at: http://0.0.0.0:10000
   ==> Your service is live
   ```

7. When the status shows **Live**, the address is at the top of the service page. For this project it is https://trustvault-15td.onrender.com.
8. Open **Environment** and copy `TV_MASTER_KEY` and `TV_AUDIT_KEY` into a password manager. Never put them in GitHub, the README, the video or the write-up.

## Part C: Prove it is secure on the live site

1. **Health:** open https://trustvault-15td.onrender.com/healthz. It shows `{"status":"ok"}`.
2. **Attack it from outside.** On your computer, in the project folder:

   ```bash
   python -m scripts.check_live https://trustvault-15td.onrender.com
   ```

   (On Windows, use `py` if `python` is not found. It uses only Python's standard library.)

   The script signs in as the demo users and checks 48 things on the live site, including: a stranger gets "not found" on every route of someone else's document, search, tags, the dashboard and the activity feed hide it, the administrator cannot download it, forged and cross-site requests are refused, the security headers and HTTPS are in place, the audit trail records real client IPs, and the audit chain is intact. Expect **48/48 checks passed**.

3. **Try it by hand:**
   1. Sign in as `advik@trustvault.test` / `Owner1_123_demo` and open **Salary letter - Akhilesh**. Copy the address from the browser bar.
   2. In a private window, sign in as `akhil@trustvault.test` / `Viewer2_123_demo` and paste the address. You see **"Document not found."**
   3. Sign in as `jeevan@trustvault.test` / `Admin_123_demo` → **Administration** → **Audit trail**, and filter **Result: Refused**. Akhil's attempt is listed, with his IP address.

All demo accounts are listed in the [README](README.md#demo-accounts).

## Part D: Updating, resetting and backups

- **Update the site:** push to `main` on GitHub. Render rebuilds and redeploys by itself; watch **Events** until it says **Live**.
- **Redeploy without a code change:** service page → **Manual Deploy** → **Deploy latest commit**.
- **Reset the demo data:** on the free plan it resets every time the service restarts, so a manual deploy resets it. On a paid plan with a disk, open the **Shell** tab, run `python -m scripts.seed --reset`, then restart the service.
- **Keep data permanently (paid):** in `render.yaml`, change `plan: free` to `plan: starter` and remove the `#` in front of the four `disk:` lines. Commit, push, then on Render open **Blueprints → trustvault → Manual sync** if it does not apply by itself.
- **Backup (paid plan with a disk):** in the **Shell** tab, run `sqlite3 /data/trustvault.db ".backup /data/backup.db"`. Store backups and `TV_MASTER_KEY` separately; neither is useful without the other.

## When something goes wrong

Open the service's **Logs**. The first error line usually says what failed.

| What you see | Cause and fix |
|---|---|
| Blueprint says no `render.yaml` was found | `render.yaml` is inside a subfolder. It must be at the top of the repository, and **Blueprint Path** must be `render.yaml`. |
| Build fails at `pip install` | `requirements.txt` is missing or was edited. Restore it and push. |
| `\r: not found` or `set: Illegal option -` | `docker-entrypoint.sh` has Windows line endings. `.gitattributes` prevents this; check it is in the repo, then run `git add --renormalize .`, commit and push. |
| `TV_MASTER_KEY is not set` or `must be 32 bytes, base64-encoded` | The service was created by hand instead of from the Blueprint, or a key was cut short. Add both keys in **Environment** (generate each with `python -c "import secrets,base64;print(base64.b64encode(secrets.token_bytes(32)).decode())"`) and redeploy. |
| Status stuck on **Deploying**, then the health check fails | Do not set a `PORT` variable yourself and do not change the Dockerfile's start command. Check the first error in **Logs**. |
| Sign-in returns straight to the sign-in page | The site was opened with `http://` or from an old tab. Use the `https://` link. |
| Every button says **"Cross-origin request refused"** | `TV_TRUSTED_PROXIES` is missing or not `1`, so the app thinks the request came over plain HTTP. |
| `check_live` fails "audit records real client IPs" | `TV_FORWARDED_FOR_HOPS` is missing. It must be `2` on Render. |
| "Too many sign-in attempts" | The sign-in rate limit. Wait 15 minutes, or redeploy (free plan). |
| Uploads or shares disappeared | Expected on the free plan: data resets when the server sleeps or restarts. |
| The first page takes about a minute | Expected on the free plan: the server was asleep. |
| The service shows **Suspended** | The month's free hours or bandwidth ran out, or the email address is not verified. |

## Running it somewhere else

### On your own computer

See [Run it locally](README.md#run-it-locally-from-a-clean-clone) in the README. In development the app creates its own keys in `instance/dev_keys.json`.

### PythonAnywhere (free, keeps data)

1. In a **Bash** console:

   ```bash
   git clone https://github.com/PailaJeevan/trustvault.git
   cd trustvault
   python3.13 -m venv ~/tv-venv && source ~/tv-venv/bin/activate
   pip install -r requirements.txt
   mkdir -p ~/trustvault-data
   cp .env.example .env && nano .env
   ```

2. In `.env`, set `TV_DATABASE_PATH=/home/<username>/trustvault-data/trustvault.db` and paste two different keys into `TV_MASTER_KEY` and `TV_AUDIT_KEY`. Keep `TV_TRUSTED_PROXIES=1` and `TV_SQLITE_JOURNAL=DELETE`. **Do not** set `TV_FORWARDED_FOR_HOPS`: PythonAnywhere has one proxy, so the default is right.
3. Run `python -m scripts.seed`.
4. **Web** tab → **Add a new web app** → **Manual configuration**, same Python version. Set source code and working directory to `/home/<username>/trustvault` and the virtualenv to `/home/<username>/tv-venv`.
5. Replace the WSGI file's contents with:

   ```python
   import sys
   sys.path.insert(0, "/home/<username>/trustvault")
   from wsgi import app as application  # noqa
   ```

6. Turn on **Force HTTPS**, click **Reload**, and run `check_live` against `https://<username>.pythonanywhere.com`.

### Fly.io, Railway or any Docker host

Use the same `Dockerfile`. Mount a persistent volume at `/data`, set `TV_MASTER_KEY`, `TV_AUDIT_KEY` and `TV_DEMO_MODE=1`, and set `TV_TRUSTED_PROXIES` and `TV_FORWARDED_FOR_HOPS` to match that host's proxies. Then run `check_live`: if "audit records real client IPs" fails, the hop count is wrong.
